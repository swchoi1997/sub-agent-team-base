TL;DR

?무엇인가

TypeSafe AI의 비생성형 판단 모델. 입력은 state(텍스트·JSON, 1.14부터 이미지)와 questions(Choice·Score·Noul·Box). 출력은 미리 정한 선택지 중 하나와 선택지별 확률, confidence다. 텍스트를 만들지 않으니 타입 오류와 파싱 실패가 원천적으로 없다.

⚡왜 빠른가

토큰 디코드 루프가 없다. 상태를 한 번 인코딩하고, 모든 질문을 격리된 가지로 병렬 평가해 확률 헤드에서 바로 읽는다. 응답 70–500ms, 입력 100만 토큰당 $0.042, 출력 무료 공식. 학습은 확률이 실제 적중률과 맞도록 하는 RLCD로 한다(세부 비공개).

→어떻게 쓰나

Jev는 System 1(빠른 직관) 역할만 맡는다. 판단은 원자적 질문으로 쪼개고, 결합·규칙·계산은 코드로 처리하고, confidence가 낮으면 사람이나 LLM(System 2)으로 넘긴다. 이 라우팅 구조가 핵심이다. 독립 평가에서는 강점(제로샷 95–99%)과 약점(yes/no를 맞바꾸면 50.5% 뒤집힘)이 함께 보고됐다.

01

개요: Jev는 무엇인가

LLM은 사람이 읽을 텍스트를 만들도록 설계됐다. 코드가 소비할 판단을 LLM에 맡기면 텍스트를 구조로 억지로 바꾸고 다시 파싱해야 한다. Jev는 이 불일치를 없애려고 만든 모델이다. 창업자는 Jev를 “프런티어 지능 함수 호출(frontier-intelligence function call)”이라고 부른다.

02

배경: System 1 vs System 2

카너먼의 이중 처리 이론에서 System 1은 빠르고 자동적이며 직관적인 판단이고, System 2는 느리고 노력이 드는 숙고형 추론이다. TypeSafe의 주장은 이렇다. 소프트웨어 안의 판단 대부분은 “어느 버킷인가?”, “긴급한가?” 같은 System 1형 판단인데, 지금까지는 System 2(추론형 LLM)를 빌려 와 그 일을 시켜 왔다.

회사 주장, 근거 미공개

“System 1은 오류가 잦다는 함의가 있지만, System One 모델은 대안보다 더 신뢰성 있게 만들 수 있다”는 주장의 근거는 아직 공개되지 않았다.

2.1 Jev 설계에서 System 1이 뜻하는 것

공식 문서의 기준은 이렇다. 각 질문은 “올바른 맥락이 주어졌을 때 해당 분야 전문가가 몇 초 안에 내릴 수 있는 직감 판단(gut-check)”이어야 한다. 긴 추론이 필요하거나 독립 요인 여러 개를 저울질해야 하는 질문은 분해해서 요인별로 따로 묻고, 결합은 코드로 한다.

03

아키텍처

Jev 내부는 비공개다. 아래 내용은 무엇이 공식이고 무엇이 추론인지를 구분해서 읽어야 한다.

3.1 공식적으로 공개된 것 vs 추론된 것

공식 TypeSafe는 새 모델 아키텍처, 최대 효율을 위한 병렬 샘플러(parallel sampler), 학습법 RLCD로 이뤄진 “새 스택”을 만들었다고 밝혔다. 샘플링은 “한 번의 쿼리에서 모든 출력을 생성”하고, Jev는 “작지도 않고 LLM도 아니다”라고 했다. 내부 구조는 공개하지 않았다.

블랙박스 추론 독립 연구자 Archer Hume은 jev-1.13.0에 약 10,000건의 블랙박스 API 호출을 보내 다음을 추론했다(JevDirectory.org 요약 기준). 소스 코드가 아니라 행동 관찰에 근거한 추정이다.

3.4 오픈 재현: 투명한 아키텍처 예시 (NDM-Block) 공개 재현

브라질 Softplan 연구진의 Narrow Decision Models(arXiv 2610.25553)는 같은 인터페이스를 공개된 구조로 구현했다.

  • 요청을 접두사 트리(state → 질문 → 선택지)로 직렬화하고, 양방향 인코더(mmBERT)에 블록 어텐션 마스크를 건다.
  • 논리적 위치(logical positions): 형제 선택지들이 같은 위치 번호를 공유하고 서로를 보지 못한다. 그래서 선택지 순서 불변성과 질문 격리가 학습된 성질이 아니라 구조적으로 보장된다.
  • state는 자기 자신만 보므로 KV를 캐시해 정확히 재사용할 수 있다. 상태 인코딩은 256토큰에 6.5ms, 4,096토큰에 59ms였다. 캐시된 state에 질문을 하나 더 붙이는 비용은 0.8–4.9ms였다.
$$M_{tu}=\begin{cases}0 & \text{block}(u)\in\{\text{block}(t)\}\cup\text{anc}(\text{block}(t))\\ -\infty & \text{otherwise}\end{cases}$$

04

수식

Jev 응답의 숫자들이 어떻게 계산되는지, 그리고 그 숫자를 어떻게 해석해야 하는지 정리한다. 슬라이더로 직접 바꿔 보자.

4.1 확률 헤드 (Choice)

$$z_i = \mathbf{w}_i^\top \mathbf{h} + b_i,\qquad p_i=\frac{e^{z_i}}{\sum_{j=1}^{K}e^{z_j}},\qquad \hat{y}=\arg\max_i p_i$$

선택지가 요청마다 바뀌므로 \(\mathbf{w}_i\)는 고정 가중치가 아니라 선택지 텍스트를 읽어 만든 벡터로 보는 것이 타당하다(Hume 분석 해설의 해석).

  • 모든 로짓에 같은 상수를 더해도 결과가 같다(shift-invariant).
  • \(\ln(p_i/p_j)=z_i-z_j\). 독립 채점이라면 선택지를 추가해도 이 값은 변하지 않아야 한다. Jev에서 −0.28 이동이 관측된 것이 listwise의 증거다.

4.2 Noul (예/아니오)

$$P(\text{yes}) = \sigma(z)=\frac{1}{1+e^{-z}}$$

Noul에는 별도 confidence가 없고 확률 자체가 답이다. 0.5 근처는 “모르겠다”는 뜻이다. 공식 시작 임계값은 yes ≥ 0.7, no ≤ 0.3이고, 그 사이는 사람에게 넘기라고 권한다 공식. 같은 척도로 쓰려면 \(\text{conf}=|2p-1|\)로 계산한다.

4.3 Score (순서형 루브릭)

레벨 \(0..n-1\)(최대 10개)에 대한 분포 \(p_i\)에서 기대값을 점수로 쓴다.

$$\text{score}=\sum_{i=0}^{n-1} i\cdot p_i$$

예: OpenRouter의 실제 호출에서 버그 심각도 확률이 (0, 0.79, 0.21)이었으므로, score = 0.79×1 + 0.21×2 = 1.21이다.

4.4 confidence 공식 공식 문서

Choice (n개 선택지, 최고 확률 \(p_{\max}\)):

$$\text{conf}=\frac{p_{\max}-\frac1n}{1-\frac1n}$$

균등 분포면 0, 확신이면 1이다. 최고 확률만 보기 때문에 (0.6, 0.3, 0.1)과 (0.6, 0.2, 0.2)는 둘 다 0.4다.

4.5 보정(calibration)과 평가 지표

보정이란 “0.8이라고 말한 답들 중 약 80%가 맞는” 성질이다. 개별 답이 아니라 집단 단위로만 성립한다.

$$\text{ECE}=\sum_{b=1}^{B}\frac{|B_b|}{N}\,\big|\text{acc}(B_b)-\text{conf}(B_b)\big|,\qquad \text{Brier}=\frac1N\sum_n\sum_k (p_{nk}-c_{nk})^2$$

관측 Hume은 MMLU 1,200문항에서 ECE 0.031(0.0313)을 측정했고, 새로 생성한 문제로도 확인했다. 3자리 곱셈은 신뢰도 83%에 정확도 86.7%였고, 문장제는 30%에 32%였다.

4.6 학습 목표: RLCD (Reinforcement Learning for Calibrated Decisions)

RLHF

사람 선호를 최적화한다.

RLVR

검증 가능한 정답을 최적화한다.

RLCD

“인식적으로 정직한 확률을 가진 판단”을 최적화한다. 확률은 결과(outcome)에 맞춰 최적화된다 공식. 예제 형식, 보상 함수, 손실은 비공개다.

공개 재현 eve-rlcd 등은 선택지 \(a\sim p\)를 샘플링하고, 정답 여부 \(c_a\in\{0,1\}\)에 대해 \(r_a=c_a-p_a\)를 보상으로 준다. 이때 REINFORCE의 기대 그래디언트는 정확히 Brier 점수 그래디언트의 −1/2배다(NDM 논문 식 3).

$$\mathbb{E}_{a\sim p}[r_a\nabla\log p_a]=\sum_a(c_a-p_a)\nabla p_a=-\tfrac12\nabla\sum_a(p_a-c_a)^2$$
  • 왜 “정답=1, 오답=0” 보상이 아닌가: 그런 보상은 정확도만 최적화한다. strictly proper scoring rule이 아니어서 과신하는 모델이 나온다. Brier나 로그 손실 같은 strictly proper scoring rule은 참 확률을 그대로 말할 때만 기대 점수가 최대가 된다.
  • 오픈 모델 Laya: 로짓에 가우시안 노이즈를 넣어 탐색하고, 보상은 log + spherical(+Score에는 순위 확률 점수 RPS)을 쓴다. 갱신은 그룹 평균 기준선을 쓰는 REINFORCE다.
  • 라벨을 이미 아는 경우에는 RL 없이 proper scoring rule을 직접 최소화해도 같은 최적점에 분산 없이 도달한다(NDM 논문의 선택).
주의

이 절의 수식은 공개 재현(eve-rlcd, Laya, NDM)의 것이다. Jev의 실제 손실 함수라는 보장은 없다.

5.2 인지 구조 측면: 분해 → 직감 → 코드 → 라우팅

빠름의 진짜 원천은 모델만이 아니라 역할 분담 구조다.

신뢰도 기반 라우팅 (System 1/2 캐스케이드):

$$\text{output}(x)=\begin{cases}f_{S1}(x) & \text{conf}(f_{S1}(x))\ge\theta\\ f_{S2}(x) & \text{otherwise}\end{cases}\qquad C = C_1 + r\cdot C_2$$

r은 에스컬레이션 비율이다. 이 구조는 System 1이 보정되어 있을 때만 안전하다.

임계값은 위험에 비례시킨다: 같은 시스템 안에서도 행동마다 임계값을 다르게 둔다. 잔액 조회 같은 읽기 전용 작업은 낮게, 송금 승인 같은 파괴적 작업은 0.9 이상으로 둔다. 하한 0.5는 “진짜 모르는” 경우를 거른다 공식.

5.3 원리 정리: 무엇이 빠른 직관을 신뢰 가능하게 만드는가

1. 출력 공간을 미리 닫는다

타입 오류와 환각된 선택지가 수학적으로 불가능하다.

2. 확률을 보정한다 (RLCD)

“모른다”를 숫자로 말하므로 코드가 멈출 때를 안다.

3. 질문을 격리한다

질문 사이의 오염(context-rot)이 없다.

4. 판단과 정책을 분리한다

모델은 확률만 내고, 무엇을 할지는 코드의 임계값이 정한다. 감사(audit)용으로 요청 ID, 질문명, 확률, 적용 임계값을 로그로 남긴다.

6.3 판단 원리를 손으로 구현한 학습용 코드 (API 없이 실행 가능)

6.4 계층 판단 예제: 품목 분류 트리 (공식 cookbook)

ERP의 품목 분류 체계나 조직도처럼 트리 구조를 가진 판단은, 노드마다 자식들을 선택지로 하는 Choice를 한 번씩 던진다.

  • Greedy: 매 단계 최고 확률 자식으로 내려간다. 초반 실수를 되돌릴 수 없다.
  • Beam(K): 경로 K개를 유지한다. 경로 점수는 간선 확률의 기하평균 \((\prod p_e)^{1/d}\)이다. 깊은 리프가 결정 횟수가 많다는 이유만으로 불리해지지 않게 하기 위해서다. 깊이가 10을 넘으면 \(\exp(\text{mean}(\log p))\)로 계산한다.
  • 공식 결과: K=3 beam은 기대 리프 3개 중 3개, greedy는 3개 중 2개를 맞혔다 공식.
인터랙티브

Greedy vs Beam

가상 확률 첫 단계에서 근소하게 앞선 “사무용품”을 고른 greedy는 리프 단계에서 애매해진다. beam은 “전산 장비 → 노트북”의 확실한 경로를 찾는다.

6.5 분해 예제: 개수 세기 (모델의 약점 우회)

✗ 이렇게 묻지 않는다

“items에 과일이 몇 개인가?”를 Score나 Choice 하나로 묻는다. 공식 “jaggedness” 문서에 따르면 Jev는 수치 정밀도가 필요한 작업에 약하다.

✓ 이렇게 쪼갠다

항목마다 Noul(“items[i]가 과일 이름인가?”)을 병렬로 묻고, 코드에서 noul > 0.5인 것을 센다. 산술·날짜 계산·임계값 비교는 코드로 먼저 처리하고, 의미 판단만 Jev에 넘긴다.

독립 평가 요약

Deußer 외 (arXiv 2609.37647)

jev-1.13.0을 37개 데이터셋에서 제로샷으로 평가했다. 346,009건 요청에 든 비용은 US$10 미만이었다. IMDB·SST-2·HellaSwag·ARC에서 95–99%를 기록했고, 37개 중 27개에서 Qwen3.8-27B를, 37개 전부에서 Gemma-4-E4B를 앞섰다. 선택 확률도 잘 보정되어 있었다.

반면 Noul 이진 확률은 임계값 튜닝이 필요했다. UNFAIR-ToS에서는 튜닝으로 micro-F1이 0.50에서 0.75로 올랐다. 세밀한 분류와 루브릭 품질 판단에는 약했다.

Rafe & Das (arXiv 2610.00346)

라벨이 있을 때는 파인튜닝한 DeBERTa-v3-large가 하나를 빼고 모든 라벨 벤치마크에서 가장 정확했다(예: 0.953 vs Jev 0.913).

루브릭에서 yes/no 표기를 반대로 붙이자 Jev 답이 100개 중 50.5개 뒤집혔다. 시험한 생성형 모델은 모두 최소 16.8개, 파인튜닝된 결정 체크포인트 4종은 최대 6.5개였다.

비결정성

동일 요청을 반복하면 라벨 510개 중 4개가 바뀌었다. 확률은 0.01–1.00 범위에서 소수 둘째 자리 격자에 놓인다(감사 논문 arXiv 2609.32160 정리). OpenRouter 블로그에서도 같은 Score가 1.21과 1.17로 달랐다. 그래서 임계값은 정확한 값이 아니라 구간(band)으로 잡아야 한다.

08

권장 사항 (실무 적용 순서)

  1. 결정론으로 풀리는 것은 코드로 처리한다. 정규식이나 DB 조회가 어떤 모델보다 낫다(공식 권고).
  2. 판단을 원자적 질문으로 쪼갠다. 한 질문에는 한 가지 직감 판단만 담는다.
  3. criteria를 신입 사원 브리핑하듯 쓴다. 질문 ID는 모델에 전달되지 않으므로 모든 의미를 instructions와 criteria에 담는다. “other” 같은 탈출구 선택지도 넣는다.
  4. 임계값은 수백 개 라벨 데이터로 정한다. confidence 대비 정확도를 그려 보고, 자동 실행 구간의 오류율이 감내할 만한 선을 고른다.
  5. 위험에 비례한 임계값과 3단 경로(자동 / 확인 / 에스컬레이션)를 쓴다.
  6. yes/no 표현과 선택지 이름 민감도를 직접 테스트한다. 50.5% 뒤집힘 사례가 있다.
  7. 로그에는 state(고객 데이터)를 남기지 않는다. 요청 ID, 확률, 적용 임계값만 남긴다.
  8. 데이터 상주(on-prem)가 필요하면 Laya나 NDM 같은 오픈 대안을 검토한다(TS에서는 @receptron/laya).
09

주의 사항 (Caveats)

이름 확인

“타입스크립트에서 낸”은 회사명 TypeSafe를 잘못 들었을 가능성이 매우 높다. TypeScript와의 실제 연결 고리는 공식 SDK와 커뮤니티 도구(jev-use, jev-combinators, open-jev 등)다.

아키텍처는 대부분 추론이다

인과 디코더, prefix 캐시, MoE 등은 Hume의 블랙박스 분석에서 나왔다. 이 페이지는 공식 / 관측 / 추정 라벨로 이를 구분했다.

RLCD 세부는 비공개다

4.6절의 수식은 공개 재현(eve-rlcd, Laya, NDM)의 것이며, Jev의 실제 손실 함수라는 보장이 없다.

속도·비용 배수는 자체 평가다

193.6배와 444.6배는 TypeSafe 자체 워크플로 평가 결과이고, 회사 스스로 상단 추정치라고 밝혔다.

보정 ≠ 정답

보정은 집단 평균에서만 성립하고, confidence는 분포 집중도일 뿐이다.

급변하는 생태계

2026년 9–11월에 버전(1.13 → 1.14), 기능(이미지·Box), 경쟁 모델(2026-10-16 OpenRouter 기준 13개 제조사의 결정 모델 21종)이 빠르게 바뀌었다. 이 페이지의 자료 기준은 2026년 11월이다.

요약 · 퀴즈 · 샌드박스

한 줄 요약

Jev는 “상태 + 타입 질문 → 보정된 확률 분포”를 한 번의 병렬 패스로 내는 System 1 판단 엔진이다. 빠름은 디코드 제거·상태 1회 인코딩·질문 격리에서 나오고, 신뢰성은 RLCD 보정과 코드가 쥔 임계값 라우팅에서 나온다.

핵심 용어 카드

State / Question / Criteria / Primitive

State는 판단 대상 데이터, Question은 instructions + criteria다. Primitive는 Choice(선택지 하나), Score(순서 있는 레벨), Noul(예/아니오 확률), Box(1.14에서 추가)다.

Calibration · ECE · Brier

보정은 말한 확률과 실제 적중률이 집단 단위에서 일치하는 성질이다. ECE는 구간별 정확도와 확률의 차이를 가중 평균한 값이고, Brier는 확률과 정답(0/1)의 제곱 오차 평균이다.

strictly proper scoring rule

참 확률을 그대로 말할 때만 기대 점수가 최대가 되는 채점 규칙이다(Brier, 로그 손실). 0/1 정확도 보상은 여기에 해당하지 않는다.

Confidence vs 확률

confidence는 분포가 한쪽에 몰린 정도(집중도)를 재는 통계다. 그 답이 맞을 확률이 아니다.

RLCD vs RLHF vs RLVR

RLHF는 선호, RLVR은 검증 가능한 정답, RLCD는 결과에 맞춘 정직한 확률을 최적화한다.

Prefill · prefix caching · 질문 격리

state를 한 번 인코딩해(prefill) KV를 재사용하고, 질문 가지끼리는 서로를 보지 못하게 하는 구조다. 비용이 O(Q×S)에서 O(S)+O(Q)로 줄어든다.

listwise vs pointwise

pointwise는 선택지를 각각 독립 채점하고, listwise는 선택지들을 서로의 맥락으로 함께 읽는다. 무관한 선택지를 추가했을 때 로그 오즈가 움직이면 listwise다.

캐스케이드 · 에스컬레이션 · 위험 비례 임계값

S1의 확신이 낮을 때만 S2로 넘기는 구조다. 행동의 위험도에 따라 임계값을 다르게 둔다.
